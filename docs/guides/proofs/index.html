Proofs & stateless verification

A MerkleForge proof lets a verifier check one value against a trusted root, with no access to the tree. This is the property that makes Merkle trees useful for light clients, bridges, browsers, and embedded devices. Proofs are byte-compatible between the two languages: a proof generated by a Rust server verifies in a TypeScript client, and the other way round.

The binary proof lives in merkle-core, so a verifier can depend on the shared types:

use merkle_core::types::{LeafIndex, ProofSide};
 
/// One step on the path: a sibling hash and the side it sits on.
pub struct ProofNode<D> {
    pub hash: D,
    pub side: ProofSide,
}
 
/// Inclusion proof for one leaf of a binary tree.
pub struct MerkleProof<D> {
    pub leaf_index: LeafIndex,
    pub leaf_count: usize,
    pub path: Vec<ProofNode<D>>, // O(log n) siblings, leaf level first
}

Every verifier is a static method that takes the hash function H as its first argument. The binary proof type lives in @merkleforge/core, so a verifier can depend on the shared types:

import type { Bytes } from '@merkleforge/core'
 
/** Which side of the running hash a proof sibling sits on. */
export type ProofSide = 'left' | 'right'
 
/** One step on the path: a sibling hash and the side it sits on. */
export interface ProofNode {
  readonly hash: Bytes
  readonly side: ProofSide
}
 
/** Inclusion proof for one leaf of a binary tree. */
export interface MerkleProof {
  readonly leafIndex: number
  readonly leafCount: number
  readonly path: readonly ProofNode[] // O(log n) siblings, leaf level first
}

(Proofs are plain objects; use proofDepth(proof) and isTrivialProof(proof) from @merkleforge/core for the depth and trivial-proof checks.)

The verification algorithm

1. current = H(0x00 ‖ leaf_data)
2. for each node in proof.path:
     if node.side == Left:  current = H(0x01 ‖ node.hash ‖ current)
     if node.side == Right: current = H(0x01 ‖ current ‖ node.hash)
3. return current == expected_root

BinaryMerkleTree::verifyBinaryMerkleTree.verify also rejects proofs whose structure is inconsistent: empty leaf data, leaf_index >= leaf_countleafIndex >= leafCount, a path length that doesn't match the padded size, or sides that don't match the bits of leaf_indexleafIndex. It returns false and never panicsthrows on malformed input.

The ProofVerifier trait

use merkle_core::{traits::HashFunction, types::MerkleProof};
 
pub trait ProofVerifier<H: HashFunction> {
    fn verify(expected_root: &H::Digest, leaf_data: &[u8], proof: &MerkleProof<H::Digest>) -> bool;
}

It is separate from MerkleTree so it can be implemented by a type with no tree state at all. BinaryMerkleTree<H> implements it, and its inherent verify delegates to it.

TypeScript has no static trait methods, so ProofVerifier in @merkleforge/core is a function type, with the hash function passed as an argument instead of a type parameter:

import type { Bytes, HashFunction, MerkleProof } from '@merkleforge/core'
 
export type ProofVerifier = (
  hasher: HashFunction,
  expectedRoot: Bytes,
  leafData: Bytes,
  proof: MerkleProof,
) => boolean

It is separate from MerkleTree so a verifier needs no tree state at all. BinaryMerkleTree.verify satisfies it and can be passed around as a plain function.

Light-client example

The server builds the tree and exports the root and a serialized proof. The client receives bytes, decodes the proof, and verifies, with the tree long gone.

use merkle_core::prelude::*;
use merkle_variants::BinaryMerkleTree;
use merkleforge_hash::Sha256;
 
/// What the server publishes: a root (e.g. in a block header) and proof bytes.
struct Published {
    root: [u8; 32],
    proof_bytes: Vec<u8>,
}
 
fn server(transactions: &[&str], index: usize) -> Result<Published, MerkleError> {
    let tree = BinaryMerkleTree::<Sha256>::from_leaves(transactions)?;
    let root = *tree.root().ok_or(MerkleError::EmptyTree)?;
    let proof = tree.generate_proof(LeafIndex(index))?;
    Ok(Published { root, proof_bytes: proof.to_bytes()? })
    // `tree` is dropped here.
}
 
fn client(trusted_root: &[u8; 32], claimed_tx: &str, proof_bytes: &[u8]) -> Result<bool, MerkleError> {
    let proof = MerkleProof::<[u8; 32]>::from_bytes(proof_bytes)?;
    Ok(BinaryMerkleTree::<Sha256>::verify(trusted_root, claimed_tx.as_bytes(), &proof))
}
 
fn main() -> Result<(), MerkleError> {
    let txs = ["tx:alice->bob:100", "tx:bob->carol:50", "tx:carol->dave:25"];
    let published = server(&txs, 0)?;
 
    println!("proof is {} bytes", published.proof_bytes.len());
    assert!(client(&published.root, "tx:alice->bob:100", &published.proof_bytes)?);
    assert!(!client(&published.root, "tx:alice->bob:1000", &published.proof_bytes)?);
    Ok(())
}

The repository ships the same flow as a runnable example:

cargo run -p merkle-variants --example light_client

encodeMerkleProof and decodeMerkleProof use the same bytes as the Rust to_bytes / from_bytes, so either side can be written in either language.

import { type Bytes, decodeMerkleProof, encodeMerkleProof, MerkleError, utf8 } from '@merkleforge/core'
import { Sha256 } from '@merkleforge/hash'
import { BinaryMerkleTree } from '@merkleforge/variants'
 
/** What the server publishes: a root (e.g. in a block header) and proof bytes. */
interface Published {
  root: Bytes
  proofBytes: Bytes
}
 
function server(transactions: string[], index: number): Published {
  const tree = BinaryMerkleTree.fromLeaves(Sha256, transactions.map(utf8))
  const root = tree.root()
  if (!root) throw new MerkleError({ code: 'EmptyTree' })
  const proof = tree.generateProof(index)
  return { root, proofBytes: encodeMerkleProof(proof) }
  // `tree` is garbage once this returns.
}
 
function client(trustedRoot: Bytes, claimedTx: string, proofBytes: Bytes): boolean {
  const proof = decodeMerkleProof(proofBytes)
  return BinaryMerkleTree.verify(Sha256, trustedRoot, utf8(claimedTx), proof)
}
 
const txs = ['tx:alice->bob:100', 'tx:bob->carol:50', 'tx:carol->dave:25']
const published = server(txs, 0)
 
console.log(`proof is ${published.proofBytes.length} bytes`)
console.assert(client(published.root, 'tx:alice->bob:100', published.proofBytes))
console.assert(!client(published.root, 'tx:alice->bob:1000', published.proofBytes))

decodeMerkleProof throws DeserializationError on malformed bytes. A runnable TypeScript version of the server/client split is on the Examples page.

Try it interactively on the live demo: change the claimed value and watch verification fail.

Verifying on-chain

The Rust crates have no Solidity helpers. The Solidity verifier contracts and the functions that format proofs for them ship with the TypeScript packages; switch to TypeScript to see them.

The TypeScript packages can also format a proof for the Solidity verifier contracts (MerkleForgeBinary, MerkleForgeSparse) in contracts/. toSolidityBinaryProof, toSolidityBinaryMultiProof, and toSoliditySparseProof from @merkleforge/variants turn proofs into bigint and 0x hex arguments ready for viem or ethers. The contracts hash with Keccak-256, so the tree must use Keccak256.

import { utf8 } from '@merkleforge/core'
import { Keccak256 } from '@merkleforge/hash'
import { BinaryMerkleTree, toSolidityBinaryProof } from '@merkleforge/variants'
 
// The Solidity verifiers hash with Keccak-256, so build the tree with Keccak256.
const tree = BinaryMerkleTree.fromLeaves(Keccak256, ['alice:100', 'bob:250', 'carol:75'].map(utf8))
 
const args = toSolidityBinaryProof(tree.generateProof(0))
// { leafIndex: 0n, leafCount: 3n, siblings: ['0x…', '0x…'] }, ready for viem or ethers
console.assert(args.leafCount === 3n && args.siblings.length === 2)

toSoliditySparseProof also compresses a sparse proof: empty siblings are dropped and marked in a bitmap, so calldata holds only real hashes.

What a verifier must trust

  • The root. A proof only shows that a leaf is consistent with some root. Get the root from a trusted source: a block header, a signed checkpoint, a contract.
  • The leaf encoding. Verify the exact bytes that were inserted. Agree on a canonical encoding (field order, separators, number formats) between prover and verifier.
  • Not leaf_countleafCount. The binary root doesn't commit to MerkleProof::leaf_countproof.leafCount. If the number of leaves matters, obtain it independently.
  • The key, for sparse proofs. Use verify_membership, which checks the proof's key. The deprecated SparseMerkleTree::verify does not.SparseMerkleTree.verifyMembership or verifyNonMembership, which check the proof's key against the key you pass.

From the published comparison run on a 10,000-leaf tree:

A binary proof carries ⌈log₂ n⌉ 32-byte siblings plus a side tag each, the leaf index, and the leaf count. encodeMerkleProof produces the same bytes as the Rust crate, so the MerkleForge size applies to both languages. See Serialization for encoding options.
