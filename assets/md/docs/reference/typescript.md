# TypeScript packages

MerkleForge for TypeScript and JavaScript is published on npm under the
[`@merkleforge`](https://www.npmjs.com/org/merkleforge) scope. It implements the same trees,
hashes, and proof formats as the Rust crates, with an idiomatic TypeScript API. The source lives
in [1888-Labs/MerkleForge-ts](https://github.com/1888-Labs/MerkleForge-ts).

* **Runtimes:** Node.js 22+, browsers, Deno, and Bun. ESM only.
* **Dependencies:** the only runtime dependency is [`@noble/hashes`](https://github.com/paulmillr/noble-hashes).
* **Compatibility:** roots and proofs match the Rust crates byte for byte. A proof generated by a
  Rust server verifies in a browser, and the other way round. This is tested against vectors
  generated by the Rust crates.

## Packages

| Package | Role | Rust equivalent |
|---------|------|-----------------|
| [`@merkleforge/core`](https://www.npmjs.com/package/@merkleforge/core) | `HashFunction` and `MerkleTree` interfaces, proof types, `MerkleError`, byte helpers, proof codecs | `merkle-core` |
| [`@merkleforge/hash`](https://www.npmjs.com/package/@merkleforge/hash) | `Sha256`, `Keccak256`, `Blake3` | `merkleforge-hash` |
| [`@merkleforge/variants`](https://www.npmjs.com/package/@merkleforge/variants) | `BinaryMerkleTree` (with multiproofs), `SparseMerkleTree`, `MerklePatriciaTrie`, proof codecs, Solidity proof formatting | `merkle-variants` |
| [`@merkleforge/hash-wasm`](https://www.npmjs.com/package/@merkleforge/hash-wasm) | WebAssembly `Keccak256` and `Sha256` with identical output, about 6x faster Keccak-256 | TypeScript only |
| [`@merkleforge/ethereum`](https://www.npmjs.com/package/@merkleforge/ethereum) | Verify `eth_getProof` account and storage proofs against a state root | TypeScript only |
| [`@merkleforge/openzeppelin`](https://www.npmjs.com/package/@merkleforge/openzeppelin) | Drop-in `StandardMerkleTree` and `SimpleMerkleTree` for `@openzeppelin/merkle-tree`: same roots, proofs, and dumps | TypeScript only |

The repository also contains Solidity verifiers for every Keccak-256 proof type
(`MerkleForgeBinary`, `MerkleForgeSparse`, `MerkleForgePatricia`, `MerkleForgeEthereum`); see
[contracts/](https://github.com/1888-Labs/MerkleForge-ts/tree/main/contracts).

```bash
npm i @merkleforge/core @merkleforge/hash @merkleforge/variants
```

Staging builds from the `develop` branch are published under the `next` dist-tag
(`npm i @merkleforge/variants@next`).

Releases are published from CI through npm trusted publishing with provenance, and a maintainer
approves each version with 2FA before it goes live.

## How the API maps

| Rust | TypeScript |
|------|------------|
| `BinaryMerkleTree::<Keccak256>::new()` | `new BinaryMerkleTree(Keccak256)` |
| `BinaryMerkleTree::<Keccak256>::from_leaves(data)?` | `BinaryMerkleTree.fromLeaves(Keccak256, data)` |
| Generic `H: HashFunction` type parameter | `HashFunction` object passed at construction and to static verifiers |
| `BinaryMerkleTree::<H>::verify(root, leaf, &proof)` | `BinaryMerkleTree.verify(H, root, leaf, proof)` |
| `Result<T, MerkleError>` | Throws `MerkleError`; check `error.code` or use `isMerkleError(error, 'EmptyTree')` |
| `[u8; 32]` digests, `&[u8]` data | `Uint8Array` (`Bytes`) |
| `b"alice"` | `utf8('alice')` |
| `LeafIndex(usize)` | `number` |
| `ProofSide::Left` / `Right` | `'left'` / `'right'` |
| `proof.depth()` / `proof.is_trivial()` | `proofDepth(proof)` / `isTrivialProof(proof)` |
| `tree.leaf_count()`, `tree.height()` | `tree.leafCount`, `tree.height` (getters) |
| `snake_case` methods | `camelCase` methods (`generate_proof` → `generateProof`) |
| `impl MerkleTree for SparseMerkleTree` (index-addressed) | `smt.indexed()` returns a `MerkleTree` view |
| `serde` on proofs | `merkleProofToSerdeJSON` / `merkleProofFromSerdeJSON` (same JSON as `serde_json`) |
| `Serializable::to_bytes` on proofs (bincode) | `encodeMerkleProof` / `decodeMerkleProof` (same bytes) |
| `no_std` + `alloc` | Not applicable |

The guides show both languages side by side: use the **Rust / TypeScript** switch in the sidebar
(or the bar at the top of the page on small screens).

## Versioning

The npm packages are versioned independently of the Rust crates (for example npm `0.2.1` alongside
crates `0.5.1`). Compatibility is defined by the **formats**, not the version numbers: the hashing
scheme, proof structure, and the bincode and JSON proof encodings are shared, and the TypeScript
test suite checks them in CI against vectors generated by the Rust crates. Release notes are on
[GitHub Releases](https://github.com/1888-Labs/MerkleForge-ts/releases).

## What only one language has

| Feature | Rust | TypeScript |
|---------|------|------------|
| Binary, Sparse, and Patricia trees, multiproofs | ✓ | ✓ |
| SHA-256, Keccak-256, BLAKE3 | ✓ | ✓ |
| `no_std` support | ✓ | — |
| WebAssembly hashes | — | ✓ `@merkleforge/hash-wasm` |
| OpenZeppelin `StandardMerkleTree` drop-in | — | ✓ `@merkleforge/openzeppelin` |
| `eth_getProof` verification | — | ✓ `@merkleforge/ethereum` |
| Solidity proof formatting and verifier contracts | — | ✓ |
